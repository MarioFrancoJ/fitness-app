# Regla de Internacionalización (i18n)

Esta regla es obligatoria para todo el trabajo en este proyecto.

## Principio

Cualquier funcionalidad nueva, página, componente, texto visible al usuario o modificación de contenido debe implementarse simultáneamente en inglés y español. No se acepta trabajo que rompa la paridad entre idiomas.

## Reglas obligatorias

1. **Doble idioma siempre.** Toda clave nueva debe agregarse tanto en `messages/en.json` como en `messages/es.json` dentro de la misma tarea. Nunca se edita un solo archivo.
2. **Estructura idéntica.** `en.json` y `es.json` deben mantener exactamente el mismo conjunto de claves y la misma jerarquía en todo momento. `en.json` contiene el texto en inglés; `es.json` contiene la traducción al español.
3. **Sin textos hardcodeados.** Los componentes nuevos no pueden contener texto visible al usuario escrito directamente en el JSX/código. Todo texto visible debe leerse del diccionario.
4. **Copy en ambos idiomas.** Cualquier cambio de copy (título, subtítulo, botón, mensaje, toast, etiqueta, placeholder visible, etc.) debe actualizarse en `en.json` y `es.json` en la misma tarea.
5. **Internacionalizado desde el inicio.** Toda página o módulo nuevo debe quedar conectado al diccionario desde su primera versión, no como paso posterior.
6. **Placeholders y variables consistentes.** Los tokens de interpolación (`{name}`, `{count}`, `{n}`, `{msg}`, etc.) deben ser idénticos entre `en.json` y `es.json`. No se traducen ni se renombran los tokens.

## Cómo consumir el diccionario

- **Client components** (`"use client"`): `import { useDictionary } from "@/lib/i18n/DictionaryProvider"` y luego `const { dict } = useDictionary();`.
- **Server components**: `import { getDictionary } from "@/lib/i18n/getDictionary"` (async, recibe `locale`).
- El tipo `Dictionary` se deriva de `messages/en.json` (`typeof en`), por lo que TypeScript detecta claves faltantes automáticamente.
- Interpolación: usar `t.clave.replace("{token}", String(valor))` (encadenar `.replace` para múltiples tokens).
- Arrays de etiquetas a nivel de módulo → convertir en funciones builder que reciben el slice del diccionario; helpers que devuelven texto UI deben recibir el slice como parámetro. Nunca llamar `useDictionary()` fuera de un componente React.

## Qué NO se traduce

- Marca/logo (`common.appName` = "Movive").
- Valores de datos/enums de base de datos usados como claves de lógica (se muestran vía un helper que mapea valor → diccionario).
- Unidades y siglas técnicas neutrales (`kcal`, `JSON`, `CSV`, `SMS`, `AI`, etc.) cuando aplique.

## Verificación (obligatoria antes de cerrar cualquier tarea con cambios de texto)

Confirmar estructura idéntica:

Debe imprimir `identical true` con el mismo número de claves en ambos archivos.
